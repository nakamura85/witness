# 见证者（Witness）· v2.9 手绘漫画风二战亚洲战场叙事游戏

> 二战的历史不是从 1937 年才开始的。要还原事实，就得从源头讲起——1895 年的马关条约、1910 年的日韩合并条约，殖民如何一步步吞下朝鲜半岛与台湾地区，直到 1931 年九一八、1937 年的南京。

一款 **2D 叙事严肃游戏**（Godot 4.7.2 .NET / C#）。

## 美术风格

**手绘上色漫画风（Hand-drawn cel-shading manga）** —— 粗墨描边、平涂色块、卡通高光，参考《勇敢的心：世界大战》的手绘质感。游戏采用**混合美术管线**，贴图层与程序化绘制共用同一坐标系，保证整画风格统一：

- **程序化手绘层（纯 `Node2D._Draw()`）**：UI / 菜单 / 暴风雪·飘雪·灯笼光晕·暗角等特效、尸体与血迹、地形细节（沙袋、桥墩、桁架、弹坑、铁轨、碉堡），风格统一入口为 `scripts/InkStyle.cs`（墨色描边 `InkColor` + 平涂色板 + `PenStroke` 工具方法）。
- **AI 生成贴图层（图生图，保持同款水彩漫画画风）**：
  - **史实军服角色立绘**（`assets/art/sprites/`）：东北军 1931 灰蓝棉服护耳棉帽青天白日帽徽、日军昭五式大檐帽黄星三八式步枪；含立姿 / 据枪 / 蹲 / 匍匐专姿（`soldier_na_aim` / `_crouch` / `_prone`）、**阵亡尸体**（`corpse_na/ija_prone/supine` 俯卧 / 仰卧）、NPC / 难民 / 建筑 / 道具。
  - **视差背景贴图**（`assets/art/backdrop/`，layer by layer 厚度 / 纵深感）：雪山 `mountains`、东北民居村落（战后残破）`village_ruined`、榆树 `tree_elm`、白桦 `tree_birch`、柳丛 `willow`、雪地枯草 `grass`，以 `DrawTextureRect` + `DrawSetTransform` 合成进 Far / Mid / Near / Fore 四层视差。
  - **战场物件贴图**（`assets/art/props/`）：沙袋掩体堆 `sandbags`、弹药木箱 `crate`、可进入的残破 / 焚毁近景民居 `house_ruined_near` / `house_burned_near`、含桥墩桁架的江桥 `bridge`，与角色 / 背景同一管线出图。
- **图层**：4 层视差（Far 0.06 / Mid 0.24 / Near 0.55 / Fore 1.32；ZIndex Far -40 / Mid -30 / Near -20 / Player 0 / Enemy 2 / Fore 5）。贴图层与程序化层叠加产生厚度与纵深。

## 游戏流程

1. **内容警告** → **标题画面**（`assets/art/title.jpg` 古城墙雪景照片全屏铺底 + 程序化叠层：飘雪粒子 + 灯笼暖光晕 + 暗角 vignette，手绘漫画风菜单）

3. **纸条档案**（《马关条约》《日韩合并条约》原文、殖民动机、历史代价）

6. **通关档案** → 史料馆

### v2.6 枪边残影根修 + 动态烟与火

### v2.9 贴图缓存串色根修 + 埋雪重做 + 验收图不再污染正式图库

- **`SoftSnow` 缓存 key 串色根修（本轮最硬的一个 bug）**（v2.9）：软衰减贴图按「颜色 + alpha」缓存，但 key 写的是 `tint.GetHashCode() ^ (int)(alpha*1000)`。Godot 的 C# `Color.GetHashCode()` 把 R/G/B 从 float **直接截断成 uint**（`0.90f` 和 `0.55f` 都变成 `0`），而且**不算 alpha**——于是所有颜色哈希到同一个数，key 里只剩 alpha 一个变量。结果是：**任何两个用了相同 alpha 的调用方共用同一张贴图**，颜色完全被忽略。
  - 现场表现：尸体旁边本该是浅色雪堆的地方，拿到的是 `EnterableHouse` 缓存的**近黑屋影**贴图，雪面上凭空多出一块硬边深灰多边形；反过来，深色阴影又会拿到浅色贴图而消失。
  - 修法：key 改为按 `R/G/B/A` 的确切字节拼装（`((int)(tint.R*255)<<24) ^ … ^ (int)(alpha*1000)*7919`），保证任何两次请求都不会撞桶。
- **埋雪三档重做（视觉上原本毫无区别）**（v2.9）：旧埋深只有 5px，而整支枪才 10px 高，三档（平躺 / 半埋 / 只露枪管）画出来**几乎一模一样**。现在雪堆锚定在**雪面**（不再跟着枪一起下沉），堆体由多层软衰减团叠出真实高度与圆顶，枪身随埋深整体下沉；同时把雪堆色调校到与实测雪面（白天约 `0.74`）一致，雪堆是「融进地面」而不是「浮在地面的一块白斑」。`WeaponPickup` 与 `CorpseActor` 两处掉枪统一走这套逻辑。

### v3.28 江桥：把它从雪里"捞"出来，枕木从巧克力方块改成真枕木

> 用户实机反馈（v3.27 之后）：「**还是有点怪怪是 那么浅颜色？如果不是暴风雪的情况应该是可以清楚的吧？还有那个铁轨哦 看起来那个巧克力色的那个方块 很不现实有点被敷衍的情况 而且真实的情况那个也没有那么大块和方方正正吧应该是长条状不是吗？**」

v3.27 把画风修对了，但桥在实机里**化在雪原里**，轨道也是全关卡最假的东西。这两件事都不是审美问题，是可以量出来的。

#### 问题一：太浅 —— 是对比度，不是色相

把桥和关卡里所有参照物放在一起量：

| | 中位亮度 | p90 | 暖度 (R−B) |
|---|---|---|---|
| 雪山背景 `mountains.png` | **0.845** | 0.984 | −0.004（冷白）|
| 房子 | 0.493 | 0.956 | +0.063 |
| 榆树 | **0.309** | 0.804 | −0.008 |
| 烧毁房子 | 0.226 | 0.604 | 0.000 |
| 尸体（仰） | 0.250 | 0.470 | −0.008 |
| v3.27 桁架 | 0.431 | **0.717** | −0.012 |

两条硬约束从这张表里掉出来：

1. **前景实体都在 0.25~0.35**（榆树 0.309、烧毁房子 0.226、尸体 0.250）。v3.27 的桁架 0.431，最亮的 10% 冲到 0.717——**贴着雪山的 0.845**，整座桥的剪影就没了。所以用户说"如果不是暴风雪的情况应该是可以看清楚的"：它不是被雪遮住了，是**自己亮到跟背景一个色**。
2. **色相必须中性**。背景是冷白，任何冷蓝灰的钢构都会跟背景同色。腹杆从"暗板岩蓝"改成**中性深灰**，锈褐主梁的彩度也收掉一档。

#### 问题二：巧克力方块 —— 原图给了答案

那排"方方正正的巧克力块"是**枕木**，画成了 22×13 的横块、暖度 +0.168 的褐色糖。但：

- **方向就错了**。两条钢轨画在 `railY` 和 `railY+12`，这已经是**斜俯视**了（纯侧视的两条轨会重合成一条线）。斜俯视里枕木横跨轨道，落在屏幕上就该是一根**竖条**，不是横块。
- **桥上根本不该有枕木**。查写实原图的桥面：这座桥的桥面是**钢桥板**，轨道直接压在钢梁上，**没有道砑也没有枕木**——那是穿式桁架 + 开放桥面的标准形制，图上白纸黑字。v3.26 给它加枕木是凭空加的，那排棕块就是它。

#### 做了什么

- **① 桁架曝光对齐到 0.38**（成品中位 0.342），腹杆改中性深灰，桁架在雪山前是一道立得住的深色剪影。
- **② 桁架不再铺雪**。照片级的雪是一小块一整块，贴在深色钢构上像一排白补丁；手绘不会在每根杆的受光尖上贴一块白。
- **③ 桥墩改成解析模型**。照片里墩面的明暗是**污渍、水渍和阴影**，不是结构——按它分档出迷彩色斑，逐列均值会把两根斜撑展平成条形码，二维大模糊还是色斑。最后只能不看原图：墩子的位置靠 alpha 找，形状靠模型画（光从右上来，全关卡的影子都朝左下，左暗右亮、底边沉进河冰转暗）。手绘的混凝土墩本来就是**几块大面**。
- **④ 抠掉烘焙进 alpha 的天空**。西端桥墩是**两片混凝土夹一个 X 形钢桁架**，格子后面本该透过去看到雪山，但写实渲染把天空烘焙进了贴图，那一带 alpha 完全不透明，镂空就这么没了，墩子成了一整块灰板子。天空像素好认——又亮、又冷、又几乎没有彩度，掩膜实测正好落在交叉钢架的菱形格子里，钢构一点没伤到（3919 px）。抠掉之后 X 形自己透空了，边缘的轮廓墨线自动勾出来。
- **⑤ 枕木改成 8×18 的竖条**，间距从 34px 收到 26px。宽度按真实比例定：枕木沿轨道方向 250mm、间距 600mm，比例 0.42；8/26 = 0.31，手绘留了余量，画得更利落。

### v3.27 江桥贴图重画：跟房子、士兵、山水真正同一套画风

> ⚠️ 本节的画风方向是对的（几何不填、颜色按材质分、墨线带手绘抖动），但 **v3.28 做了三处修正**：桁架还是太浅（中位 0.431、p90 0.717，在 0.845 的雪山前化掉了）、腹杆的冷蓝要改中性深灰、枕木的巧克力方块要换成真枕木。下面的数据与描述按 v3.27 原样保留，读的时候心里有个数。

> 用户实机反馈（v3.26 之后）：「**更惨了 这为何会变成这样的风格了？我要的风格是你们这两个 需要跟着整体的游戏风格 就是 跟士兵和尸体还有那些房子 那些需要统一风格啊 你跟整个游戏的画风不同啊**」

v3.26 把桥改成手绘风的方向是对的，**做法是错的**：它是"给写实图换色"，结果做出来是一块蓝灰色的板。全部有实测数据：

|------|------------|-----------|-----------|
| 墨线占比 | 12.1% | 11.1% | **2.3%** ← 只有色块，没有线 |
| 墨线颜色 | 近黑 (0.096,0.095,0.090) | 近黑 | **暖褐 (0.188,0.152,0.134)** |
| 留白（纸底） | 16.9% | 38.0% | **10.5%** |

而且它犯了一个**几何错误**：为了抹掉铆钉噪点，把桁架的镂空网格也填成了实心。行扫描对比（row 120，x<700 段）：

```
原图    16 段构件，段段之间有缝（最宽 65px）
v3.26   4 段，其中一段 452px 连成一片
```

眼睛里这就是"一座实心的蓝灰帐篷"，根本不是钢桁架。

**v3.27 换了思路：把写实渲染当线稿来源，不当颜色来源。**

- **① 几何一个像素都不填**。只做两件事：拆检修走道栏杆（v3.26 已做）、补 1–2px 的铆钉针孔。桁架的镂空是桥的形状本身，动不得。
- **② 补孔按"内切圆半径"分级，不按面积**。半径 ≤1px 的针孔补掉；半径 ≤2px 的铆钉孔**保留几何、只抹掉围着它的墨线环**——照片上每个铆钉位置都被抠成了一个小洞，墨线沿着洞口一圈，桁架上就排满了黑方框。用开运算判"小孔"是错的，会把三角形桁架格子也吃掉（row 120 从 16 段塌成 7 段）。
- **③ 墨线 = 局部对比 + 走向长度**。比邻域中位暗 0.10 以上才算线（只抓"缝"，不抓大片背光阴影）；再按走向长度筛——**铆钉是圆点（横竖都短），缝是长线**，噪点自然消失。
- **④ 墨线加手绘抖动**。准备 9 条候选轮廓带（收缩/原位/膨胀 1px × 1/2/3px 宽），用低频噪声图挑。线于是有"落笔轻重"和"往外飘一点再回来"——照片的 alpha 边缘给不了的。
- **⑤ 颜色按材质分，不按亮度一刀切**。**锈褐主梁**（照片里的钢构本来就是暖褐的）/ **暗板岩腹杆** / **中性钢桥面** / **暖灰混凝土** / **纸白雪**。v3.26 把它染成蓝灰，是"不像同一个游戏"的主因。
- **⑥ 平涂用硬边**。分档之后不再做高斯软过渡，色块边界干脆，才像"画"出来的。
- **⑦ 曝光归一**。照片里桁架中位亮度只有 0.30 出头，直接分档会得到一堵黑墙；按区把中位亮度对齐到色板该有的位置。
- **⑧ 桥墩按列分带**。一大片混凝土，手绘圆柱体就是几道**竖向**明暗带，不是照片里那些圆斑污渍。均值只统计实体像素（否则墩面凹槽会把整列拉黑，柱子被切成条形码）。
- **⑨ 雪只落在朝上的面**。除了"极亮且几乎无彩"，还得是所在构件的上沿。少了这一条，远端桁架上会糊出一片片白斑像泼了油漆。
- **⑩ 桥面按结构分层**（顶缘受光 / 梁腹 / 底缘阴影），不再继承照片的锈迹。

### v3.26 江桥「两条路」根修 + 钢桥贴图重绘成手绘风

> 用户实机反馈：「那个桥的贴图 跟那个铁轨感觉一个是贴图另外一个铁轨是画上去的 因为这样导致好像一个桥出现了两个路的感觉」「画风要跟整体游戏风格要统一」
>
> ⚠️ 本节的「贴图重绘成手绘风」做法（给写实图换色 + 填缀条小孔洞）在 **v3.27 已被推翻重做**：它把桁架镂空填实了，颜色也偏成蓝灰。代码层的「钢桥板」改动保留有效。

- **① 「一个桥出现两条路」——根因有两层，一层在代码、一层在贴图**：
  - **代码层**：桥面贴图自带一条**铆钉大梁面**（全宽暗带），代码又在同一个高度画了一条**褐色枕木带**（全宽色带）。两条异色长条紧挨着、中间没有任何结构层，眼睛立刻把它们读成「两条并排的路」。改法是补上缺的那一层——铁路桥的轨道是**钢轨 → 枕木 → 钢桥板 → 主梁**四层，少了钢桥板，两条带子就贴在一起。现在桥面上画一道 13px 的**钢桥板**（顶面受光翼缘 + 闭合墨线轮廓），轨道层次变成 钢桥板 → 枕木 → 钢轨，三层分开。
  - **贴图层**：桥面高度上还带着一整排**检修走道栏杆**（立柱 + 上下横杆）。栏杆每一格都是被立柱和横杆围住的透明「洞」，面积不到 400px，于是被程序化贴图流程里的「填掉缀条小孔洞」一步**填成了实心**——一排栅栏变成一整条**蓝灰色实心板**，横在轨道正上方。这就是那条「第二条路」的另一半，也是之前实机截图里桁架下半部那块莫名其妙蓝灰矩形的来源。
- **② 把栏杆拆掉（贴图层）**：原图是 1931 年公路桥的钢桁架，桥面上带检修走道；这一关的主角是铁路，栏杆不该在。拆的时候颜色和位置都分不开（栏杆和桁架都是钢，偏色几乎一样；两者在同一片行里交错），能分开的是**几何**：
  - **厚度**（用距离变换量出来的构件实际厚度）：桁架主构件 25–40px 厚，缀条和栏杆立柱 4–14px 厚；
  - **上方有没有桁架延续**：桁架的斜杆立柱都是从桥面一路长到桥顶的大家伙，栏杆上面（除了横杆自己那几像素）全是天空；
  - **长横杆**：远端透视里扶手会变粗（12–20px），前两条会漏掉，靠「水平连得很长（≥40px）而竖直很薄」兜住。
  - 三条判据取并集，**只在桥面顶边以上 52 行的带子里动手**，桥面顶板本身三行不碰。合计删掉 5166 个像素：栏杆整排消失，桁架一根没少，远端的桥也没有被误伤。
- **③ 贴图重绘成手绘风**（`tools/bridge_restyle/`）：`bridge.png` 原本是一张 1.67MB 的**写实 3D 渲染**（大量纯黑像素、照片噪点），跟关卡里其它素材（奶油纸底 + 黑墨线 + 蓝灰水彩晕染 + 大面积留白的手绘插画）完全不是一套语言——放进雪原里像「另一个游戏贴进去的」。现在用程序化风格迁移重绘：
  - **alpha 轮廓与几何一个像素都不动**，只改颜色；
  - **双通道**：细节层（原图）定墨线落点，色块层（降采样 x6 + 形态学开运算）取平涂色——铆钉、节点板、腹杆这些「一台机器的照片」级细节自动消失，只剩大结构；
  - **必须预乘 alpha**：直接 `convert('L')` 会把透明区残留的黑混进灰度，天空变成一片噪点麻脸，后面无论怎么滤都回不去；
  - **墨线向内收缩**：轮廓线若由 alpha 向外膨胀得到，会画到透明区去，成品图上就是满屏芝麻黑点；改成 `alpha − MinFilter(alpha)` 向内收，再乘 alpha 掩膜，保证只画在构件上；
  - **只填小孔洞**：填 < 400px 的（缀条格构），≥ 400px 的一律留着（主桁架的大透空是桁架该有的通透感，填掉整座桥会变成一堵墙）；
  - 三档平涂（base / shadow / highlight）+ 水彩纸纹 + 去蓝提亮，实机取色对齐：场景 RGB(113,118,120)、士兵 RGB(134,137,138)、桥 RGB(131,136,139)。
- **④ 锈迹收敛**：写实渲染里钢构件的受光面跟雪一个亮度级，梁面上到处被判成雪（白片）；暖色蒙版也抓得太松，一摊一摊褐色喷溅像脏点。暖色门槛 0.075 → 0.105，材质阈值 0.62 → 0.66，锈色降饱和，桁架区一律不给雪（现实里雪积在水平面上，不会挂在斜杆上）。

| 项目 | 改动前 | 改动后 |
|------|--------|--------|
| 桥面层次 | 铆钉大梁面 + 褐色枕木带，两条平行长条 | **钢桥板**夹在中间：钢桥板 → 枕木 → 钢轨，三层分开 |
| 轨道上方 | 一整条**蓝灰实心板**（栏杆被填孔填实了） | 栏杆整排拆掉，轨道上方只剩桁架和天空 |
| 桥的画风 | 写实 3D 渲染，跟手绘关卡格格不入 | 墨线 + 水彩平涂，跟焦黑木屋 / 雪山同一套语言 |
| 桁架通透感 | 铆钉、腹杆、节点板一堆细节，像机器照片 | 只剩大构件的墨线轮廓，透空能看见远处的山 |

### v3.23 碉堡糊成灰板（mipmap）+ 桥的调子

> 用户复检：「这个尸体后面那个是什么？你确定？为何越改越差？」「你这个桥的颜色和风格跟整体游戏画风不同啊 那个颜色超级超级淡的 你确定准确的吗」

- **① 尸体后面那块是碉堡，而且被 mipmap 糊成了灰板**：那具尸体是 3870 的日军仰卧，背后的就是 3835 的碉堡。v3.22 用 `DrawTextureRectRegion` 从 1449px 宽的沙袋图里裁了 **701px** 塞进 **91px** 的框里——GPU 对这么陡的缩放直接取**最高层 mip**，整个碉堡塌成一块**边缘笔直的淡灰方板**，玩家完全看不出是什么。现在把沙袋面**预先缩成自己的小图**（`bunker_face.png` 96×60），游戏里接近 **1:1** 绘制，沙袋一颗颗看得清。

### v3.16 白板根修收尾：桁架全透空 + 房屋开口透空 + 雪化带无硬边

> 全部**本机 Godot 4.7.2 mono 实机跑通验证**：`dotnet build` 0 错误，`Capture.cs` 12 张 + `CaptureMap.cs` 5 张巡游截图**整轮 0 报错**。

- **③ 黑烟不再盖住角色**：烟层 z=1 在玩家（0）与敌兵（2/3）**之上**，焚毁村落的黑烟把走过去的人整块吞掉。现在整叠层级下移：地面艺术 -5 / 脚印 -4 / 远排房屋 -3 / 近排房屋 -2 / **烟 -1** / 玩家 0 / 敌兵 2–3 —— **烟在房子前、人后**，敌兵的轮廓与枪完全清晰。
- **④ 火与烟不再一个尺寸**：以前同类型房子共用一套写死的 `size/strength/fire/rise`，整村火苗像复制粘贴。现在**每栋房子自己抽签**：受损状态定区间、建筑宽度缩放（250px→0.72×、360px→1.15×）、区间内随机取值；大火还会多生一股细烟柱。实测同一场：烧毁大房 h2 → 烟 1.82 / 浓 0.98 / 火 0.82；快烧完的焦柱 h4 → 烟 0.27 / 浓 0.22 / 火 0.18（一丝淡烟 + 一点小火苗）。火苗尺寸**另算**（不再跟烟柱共用一个数），小到会退化成直线的火舌直接跳过 —— 否则 Godot 三角化会每帧刷 "Invalid polygon data"。

## 关卡玩法

### 嫩江江桥 1931.11.4

- **移动**：A/D 或 ←/→ 左右推进；**空格**跳跃；**S / ↓** 蹲下
- **射击**：鼠标左键（朝鼠标指向开火；立姿据枪 / 跪蹲 / 低姿匍匐按军人条令出专姿立绘）
- **记录**：靠近发光的证词点，**按住 E 约 1.2 秒**（进度环）—— 被敌兵看见时会被打断
- **解谜设计**：证言必须完整记录三份（机枪手赵永生、卫生员李桂兰、铁路工人孙德山），缺一不可通关。现场散落的物证碎片（歪把子零件、绷带卷、铁轨碎段）是完整还原证词的关键。

### v2.2 新增交互（嫩江江桥）

- **进入房屋 / 搜刮**：走到近景民居（残破 / 焚毁）前按 **E** 进入屋内，点击搜刮点（子弹 / 手榴弹 / 遗言字条 / 线索字条 / 灰烬），长按撬开**宝箱**（约 1.4 秒，60% 开出弹药+手榴弹，40% 冻锁失败）。搜索进度自动保存。
- **拾取掉枪**：日军阵亡后尸体旁会掉落步枪，靠近按 **E** 拾取——可能枪栓冻死开不了（0 弹），也可能带 2~8 发可用子弹，自动补进弹仓。
- **手榴弹**：按 **G** 投掷木柄手榴弹（抛物线 + 落地反弹 + 2.2 秒引信），范围杀伤靠近的日军；弹仓打空时优先去捡枪或进屋搜弹。
- **沙包掩体**：蹲（S / ↓）或匍匐（Ctrl / C）贴住沙墙即进入「掩体」状态，日军命中率骤降；敌兵会前压逼近。

## 如何运行（小白版，3 步）

1. **装 .NET 8 SDK**（编译 C# 必需）
   到 https://dotnet.microsoft.com/download/dotnet/8.0 下载并安装 .NET 8.0 SDK。

2. **装「.NET 版」Godot 4.7**（注意：不是普通版！）
   到 https://github.com/godotengine/godot-builds/releases 下载 **Godot_v4.7-stable_mono_win64.exe**（文件名带 `mono` 才是 .NET 版）。

3. **打开游戏**
   双击 Godot exe → 点「导入」→ 选择本项目的 `project.godot` → 打开 → 按 **F5** 运行。

> 也可以先在命令行运行 `dotnet build witness.sln` 确认编译通过（0 错误）再进 Godot。

## 内容警告

本游戏取材于二战亚洲战场的真实历史，包含战争、屠杀与性暴力的**记述与暗示**（均来自公开史料，不含血腥画面）。若你正处于创伤恢复期，请谨慎游玩。

## 给开发者的提示

- **C# 脚本文件名必须与类名大小写完全一致**，否则 Godot 会静默跳过注册
- `project.godot` 必须显式写 `[dotnet] project/assembly_name="witness"`，否则报「DLL 找不到」
- 自动截图巡游：开发时把 `scripts/Capture.cs`（或旧 `scripts/VerifyTour.cs`）临时挂到 `[autoload]` 再正常运行游戏，跑完自动退出并输出到 `docs/screenshots/`；**push 前必须移除**
- headless 测试：`Godot_v4.7-stable_mono_win64.exe --headless --path . --script res://tests/SmokeTest.cs`
- 背景贴图管线：AI 图生图生成 → `_gen/backdrop/process.py` 去白底抠图 + 紧裁 + 水印条 → 落 `assets/art/backdrop/` 并让 Godot 生成 `.import`
